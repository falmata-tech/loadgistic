All features depend on `BASE-BE-001`; user-facing features depend on `BASE-FE-001`; runtime and release constraints derive from `BASE-DEP-001`.

Cross-feature authorization contracts are mapped in `docs/AUTHORIZATION_MATRIX.md` and verified by `tests/authorization.test.mjs`.

Production deployment readiness is mapped in `docs/LAUNCH_READINESS.md` and checked by `npm run launch:check`. The command remains intentionally red until managed data, identity, rate limiting, and upload-scanning adapters are implemented.

Playwright runs through `BrowserTestRuntime` on port `3100` with `data/test-e2e.db`; it never reuses the development server or `data/loadgistic.db`.

The local visual audit (`npm run test:ui-audit`) covers logged-out and role-scoped screens at desktop and mobile sizes, including the producer homepage and About page, Fleet Transporter dashboard, company Driver capacity Home, truck-specific fleet capacity controls, My Network states, searchable Boards, pooled-shipment detail, route evidence maps and comparison, Post Shipment, categorized My Shipments and Tracking-stage controls, verification workflows, member Support New/Continue/Past states, SUPPORT queues/conversations, filtered admin Support supervision, admin Operations and Rating Reviews, assigned-shipment controls, and secret-code customer tracking. Its report checks response status, horizontal overflow, touch target size, unlabeled controls, icon coverage, empty commands, and browser errors; screenshots and `report.json` are written to the ignored `artifacts/ui-audit/` directory. The August 2026 verification run captured 226 automated screens with zero flags or browser-flow errors, followed by direct desktop/mobile About-page screenshots; the next complete run includes About in the automated route set.

The comprehensive dataset test validates all 34 application tables, more than 8,000 standard-profile rows, structured route coordinates, foreign keys, entity ownership, fleet assignments, generated authentication, mixed movement scopes, support queues, unique named network relationships, cross-member visibility, published-rating projection, and production denial. After `npm run db:stress`, `npm run test:ui-stress` captures 74 dense desktop/mobile screens across six personas, including Connected, Requests, Favorites, Partners and Direct visibility, second-page Board, Directory, and Operations results, mixed coverage comparison, and expired billing mode. It checks expected cohort content, status, browser errors, overflow, render time, DOM size, card density, and requested-page visibility. Its ignored evidence is written to `artifacts/stress-ui/`.
