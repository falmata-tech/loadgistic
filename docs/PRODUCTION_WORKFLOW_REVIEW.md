A shipment has one account partner, a shipper or broker. A broker may paste the link into their external shipment record and send the code separately. Customers can open that load without a Loadgistic account. Access ends on link revocation or expiry. The unlocked viewing session currently lasts at most five minutes, after which the customer must enter the code again.

Migration 231 separates provider requests from guest access. The broker can find a discoverable assigned truck even with no available Capacity signal. Connected providers appear first. The request records both the truck and its current driver. Reassignment requires the broker to select again. New fleet drivers receive Tracking permission by default, and managers retain control of that permission.

## Location, lifecycle and privacy

- Route pins describe saved cities. A current vehicle point requires an eligible saved report, shipment location consent and viewer permission. A new pending session or a connected session with no report must keep the route visible without putting a truck at pickup.
- Phone and GPS reports use an approximate center and the report's saved radius. The foreground phone Tracking control offers 1, 3, 5 and 10 km. The map can also render a saved 20 km report. SQL exercises a 10 km phone report, a later GPS report, wrong-source suppression, agreement boundaries and terminal removal. The map uses the reported radius. Public Capacity settings cannot silently replace an existing shipment's source agreement.
- A phone-width Chromium run exercised the driver reporting control, saved a 10 km and then a 5 km approximate phone location, checked cooldown, hidden-tab pause, permission denial and retry, and read it back through an authorized guest link. The sensor was simulated. Web route and proof workflows passed locally. The Expo guest map showed the saved 3 km area and its center without exposing truck details. The registered account could open proof, and reopening after revocation was denied. Live receiver-to-screen GPS movement and a physical phone's permission, suspension, foreground/background behavior and changing position still require evidence. The first hosted simulator window accepted zero reports.
- Duplicate connection, expiry, revoked links, changed assignment, lost team membership, source changes, missing proof, repeated approval/review and transient refresh failures are separate checks. In particular, a successful link read cannot authorize managing the broker's team or accessing a proof file.

## Release decision

**Hold the broad rollout.** The natural simulator run failed, the Android dependency check has an unresolved tooling advisory, and an installed Android build, current role-by-role acceptance and representative production-scale capacity evidence are outstanding. A local test count or successful web build cannot establish how many concurrent users the hosted system supports. Keep the public launch decision separate from the already verified signed-out Private map behavior.
